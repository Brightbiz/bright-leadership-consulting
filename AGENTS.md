Employer-funded ELM offer records share contracting identity and invoice constants from `src/data/legal.ts` so the offer, invoice, acceptance record, and Terms page stay aligned.
Both admin CSV writers use the shared export-only cell serializer to neutralise spreadsheet formula/control prefixes and escape quotes without modifying stored records.
The static description is marked as Helmet-managed so route metadata replaces it rather than creating duplicate descriptions; missing routes use SEOHead with explicit noindex.
Use gold-ink for small gold labels on light surfaces and navy-note for subdued footer text; keep decorative gold unchanged to preserve the brand while meeting contrast requirements.
The shared curriculum timeline is a labelled, focusable scroll region so keyboard users can reach every stage without whole-page overflow.
Academy discovery lives at /academy separately from the unchanged accredited executive catalogue; local comparison scroll constraints preserve page sizing and keyboard access. Public indexing is permitted only on Bright's custom domains, with per-page noindex overriding that permission, so preview discovery and webinar pages remain excluded.
The CPD information page reads provider statements and executive programme hours from the shared accreditation/catalogue data; it explicitly excludes Leading People so provider status cannot imply programme accreditation.
Chat quota count and reservation run atomically in a service-only database function; paid processing requires an explicit true response, and errors or ambiguous results deny processing.
Enquiry category keys and labels are shared between the contact form, submission allowlist, email notices and admin display; Leading People attribution is scoped to its explicit cohort URL.
Mailbox routing uses `info@brightleadershipconsulting.com` for programme/pre-purchase enquiries and `admin@brightleadershipconsulting.com` for accepted purchases, invoices, payment, access, cancellations and contractual administration, so transactional records do not mix enquiry and administration contacts.
Internal enquiry notifications send from the `submit-form` edge function via the Resend connector gateway (`_shared/resendNotify.ts`); they are best-effort and must never block or fail a form submission, and mail can only leave once `brightleadershipconsulting.com` is verified in the Resend account.
Webinar captions render in a separate strip below the video so they never obscure slide content.- Enquiry attribution (contact_submissions.enquiry_type/source) is carried only in the explicit enquiry-route URL and cleared after submission, so unrelated enquiries are never tagged; both values are allowlisted in submit-form.
- Cookie consent has two independent categories (analytics → analytics_storage, advertising → ad_*) stored as a v2 record; older records are discarded so visitors are re-asked after wording changes. gtag.js is never in index.html: it is injected only after a category is granted, and any withdrawal reloads the page so no Google script remains (it cannot be unloaded and still sends cookieless pings).
- GA4 page views come only from the config call and Enhanced Measurement history events; the app never sends manual page_view (it double-counted).
- On-hold features live in /on-hold (not deployed, not routed) until approved.
- Email design review drafts stay in `on-hold/email-design` and are never imported into public routes; this allows layout review without activating outreach or changing the website.
- Campaign tags (utm_source/medium/campaign) are held in memory only (no storage), allow-listed client- and server-side, and malformed values are dropped rather than rejecting an enquiry.
- Webinar viewing events use one-second watched slots (normal speed, no skips/replays counted) and are sent only with analytics consent and no identifiers.
- Marketing opt-ins are stored in marketing_consents with server-held consent wording keyed by version; every marketing send must exclude any email with a withdrawn record.
- Insights articles are standalone pages under /insights listed in generate-sitemap.mjs; their CTAs never add campaign tags (only carry the visitor's in-memory tags) and record origin via the consent-gated article_cta_click event.
- Sitemap lastmod dates are hand-recorded per entry in generate-sitemap.mjs, never derived from Git/file times/build date, because the publish build has no history and re-stamped every page.
- Outreach sending: every batch requires a one-time approval row in outreach_batch_approvals (fixed recipient list, content hash, sender, max count, expiry); test mode is restricted server-side to the designated test address and never touches draft state. Approvals are inserted directly in the database at approval time — there is no admin UI for them.
